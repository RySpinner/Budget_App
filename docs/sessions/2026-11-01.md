## Conversation highlights
- **Real data:** the owner shared a real Citi export with one real charge.
  - It was used only to confirm the format and to test an import into a throwaway database. That database and the archived copy were deleted afterwards.
  - The repo's test fixture copies the format with fake merchants and amounts.
  - `.gitignore` now blocks `.CSV` as well as `.csv`; Citi uses capitals.
- **Citi format:** `Status,Date,Description,Debit,Credit`, with Windows line endings and blank `,,,,` rows. The blank rows came from the owner hand-editing the file.
- **Masked card number:** the `XXXXXXXXXXXX1234` in Citi descriptions is likely a per-merchant virtual number. Last-4 card detection was built, then removed.
- **Excluded vs. refund** (explained to the owner):
  - Excluded rows (card payments, pending rows, balance transfers, rewards) are never saved as transactions, so they never count as spending.
  - A refund is saved as negative spending in its category.
  - Payments and refunds both arrive in Citi's Credit column, which is why the "Credits" reminder matters.
- **Interest and fees** count as spending, filed under Discretionary › Fees & Interest for now.
- **Windows setup:**
  - The virtual environment activates with `.venv\Scripts\Activate.ps1` (not `.venv/bin/activate`).
  - The README now has Windows and Mac/Linux commands.
  - Steps for installing Postgres on Windows are in the README.
- **"Changed parser_key in local.toml but nothing happened":** the seed only inserts, so the existing card kept `other_bank`.
  - Fix: `UPDATE cards SET parser_key = 'citi' WHERE id = …;` or recreate the database and re-seed.
  - The seed now prints a warning when this happens.
- **Adding a subcategory:** add it to `seed/categories.toml` and run `python -m budget.seed`, or use a SQL `INSERT`. No migration is needed, since categories are data, not schema.
  - Renaming or retiring: SQL for now (`active = false` rather than deleting). Rename in the TOML file too.
  - A Settings page will handle this later.
- **Bugs caught by tests or browser checks during the session:**
  - "contains" rules didn't collapse spaces in the pattern.
  - `set_splits` left constraint checking switched to immediate.
  - Two dollar amounts in one message rendered as a math formula. Fixed on every page with `app/ui.py: md()`.
